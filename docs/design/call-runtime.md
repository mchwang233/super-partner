# 调用层改进

目标：审核能力不低于执行者；会话可恢复、换模型有交接；上下文压缩保留约束和证据；
推理参数、实际用量与重试可追踪；按配置主动限流；路由使用同类任务历史；工具扩展保持原沙箱。

改动：`routing.py` 修复审核排序并加入有最低样本门槛的历史反馈；`db.py` 保存会话、
归档和调用记录；`conversation.py` 管理多供应商续接、结构化记忆及归档检索；
`providers.py` 在请求和工具边界保存状态、记录用量和有效推理参数；
`call_control.py` 控制供应商并发/RPM/TPM；`extensions.py` 提供受限工具与生命周期钩子；
`executor.py` 绑定任务与调用，`cli_channels.py` 读取 CLI 报告的用量；`progress.py`
拒绝无有效结论的进度判断；API 和结果页展示调用记录。保留已上线的产物验收和累计限额。

测试：先证明能力排序、重启恢复、推理降级缺少记录等失败；再测试跨供应商续接、
中断工具不自动重跑、摘要失败不丢原文、归档隔离、取消释放限流槽、重试计费及缺失用量、
低样本冷启动和历史反馈、钩子失败阻止执行、旧数据库兼容；最后全量后端与前端检查。

风险：历史反馈只用于相同能力/难度且样本足够的候选，不声称因果；摘要仍可能遗漏，
保留原始记录可检索；未知用量明确显示，不能当成零；工具扩展和额度默认为空，
不增加网络/宿主权限；明确合同的硬限额仍高于摘要和恢复。通过检查后按用户授权自动应用。

## 配置与边界

- `SUPER_PARTNER_PROVIDER_LIMITS`：JSON 对象，键为 provider，值可含 `concurrency`、`rpm`、
  `tpm`，均为非负整数。未提供或零表示未配置。TPM 按输入字节上界和最大输出预留，
  收到用量后改为实际报告值；丢失响应保留保守预留。429 的 Retry-After 同时影响该供应商其他请求。
- `SUPER_PARTNER_REASONING_FALLBACK`：默认 `report`，降级写入调用记录；`strict` 禁止移除
  被拒绝的推理参数。记录的强度是发送值，并不代表能观察模型内部实际推理强度。
- `SUPER_PARTNER_API_TOOL_EXTENSIONS`：工具名映射到 `command`（argv 列表）、`description`、
  `parameters`。支持 object/array/string/integer/number/boolean、required、enum 和布尔型
  additionalProperties；不支持的 schema 被拒绝。命令收到一个安全引用的 JSON 参数。
  例如工具 `ProjectCheck` 可调用项目中的 `["python3", "scripts/check.py"]`。
- `SUPER_PARTNER_API_TOOL_HOOKS`：`before_tool`、`after_tool` 各为 argv 列表的列表。
  失败的前置钩子阻止工具；失败的后置钩子明确说明工具已经运行，不能假装回滚。
  钩子配置时读取工具也串行执行。工具及钩子继承任务网络许可、超时和文件沙箱；
  不运行于只读审核或宿主环境修复。此扩展是命令适配层，不是完整 MCP 客户端或 MCP 服务发现。

历史反馈使用最近 200 个任务，每个步骤在一个模型上的所有重试作为一个样本；按能力与难度
分组，至少 8 个样本才改变成本排序。目录能力门槛、工具/视觉支持、配置与额度可用性仍先过滤。
没有可信耗时的旧记录不参与耗时指标。用户明确选择、重试和负责人切换不会被该初次路由覆盖。

CLI 解析 Codex JSONL 的 turn.completed、Claude JSON usage；其他未报告用量的通道显示未知。
费用仍按目录价格估算，缓存写入溢价依赖目录是否支持，不能当作账单；旧调用不能补造 token。
调用记录不包含 API 密钥、请求正文或供应商原始错误正文。会话/归档包含任务内容，保存在已有
受保护数据目录中，删除任务时清理。进程内限流适用于当前单服务进程部署。

升级后自动应用于下一次调用；原来取消的任务不会因此启动。真实项目的耗时、费用和返工率
改善需要后续同类任务记录验证，回归通过仅说明行为符合这些规则，不等于已证明快于 Claude Code。
