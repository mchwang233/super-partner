# 任务结束后的复盘与改进

任务结束后，从执行记录生成结论和有证据的改进项，验证后供后续任务使用，并记录应用效果。
原有统计复盘继续保存；新的模型复盘在后台运行，其失败不改变原任务的结束状态。

## 开启和预算

在结果页的「复盘与改进 → 自动改进设置」开启。为了兼容已有安装，自动复盘初始关闭；
开启后，成功、失败、未完成、取消的任务均会触发。也可对已结束的任务点「生成复盘与改进项」。
旧任务不会因服务升级而批量产生模型费用。

每次复盘有单独显示的额外预算，默认 $0.50，包括结论生成、建议验证及分配给平台工程师的额度。
平台工作的预算是从剩余额度分配的，不重复追加。预算不足会停止复盘，保留结论、改进项及已花费用；
调整预算后可以继续。无可用模型时记录原因，不制造复盘结论。

复盘分析和改进验证按模型库的综合能力评分优先选择最强的可用模型，评分相同时比较规划能力、
可靠性；价格、API/CLI 通道及普通子任务的 API 优先策略不影响此选择。仍尊重模型启用状态、
可用额度、任务的 CLI 许可和上下文容量。验证使用独立的空白会话；有同等能力的另一模型时优先
交叉验证，否则仍使用最强模型，不为了换模型而降级。推理强度沿用诊断设置
`SUPER_PARTNER_DIAGNOSIS_REASONING_EFFORT`（默认 high）。预算不足会暂停，不切换到便宜弱模型。

设置通过 `/api/improvements/settings` 持久化。没有持久化设置时读
`SUPER_PARTNER_LEARNING_ENABLED`（默认 false）、`SUPER_PARTNER_LEARNING_BUDGET_USD`（默认 0.5）、
`SUPER_PARTNER_LEARNING_AUTO_PLATFORM`（默认 true）。不需要新依赖或本机路径设置。

## 结论和改进项

复盘模型收到原需求、步骤结果、检查记录、工具调用摘要、统计复盘和反复出现的问题。
输出中文结论，以及最多三项改进；没有充分证据时允许没有改进项。每项必须引用真实步骤，
说明适用工具或任务能力、改进内容、预期收益。不能引用没有记录的问题，也不能自行设置为已验证。
相同内容和适用范围的现有改进会去重。

改进分为：

- **Skill**：完整的 SKILL.md，以及可在空白步骤沙箱中重现的小例子和断言。控制器实际执行检查，
  记录退出结果和输出，再由一次独立模型调用判断检查是否验证了所提经验。通过后保存到数据目录
  `learned-skills/<改进项 id>/SKILL.md`，以独立版本加入后续任务的指令。
- **执行规则**：关于任务规划和执行的具体建议，由独立验证调用根据原始证据和反例评估。它们是
  有适用范围的建议，不能覆盖用户要求、验收标准、预算限制或平台权限。实际收益等待后续任务衡量。
- **平台改进**：平台代码、调度行为、平台规则和通用技能的修改交给现有平台工程师。工程师在副本中
  生成方案、实施并执行独立检查，然后进入已有的生效、重启和健康检查流程。
  默认自动应用测试通过的复盘改进；关闭「平台改进通过独立测试后自动应用」后，使用现有审批流程。
  若工程师提出真正需要用户决定的问题，保留待回复状态。只有实际生效后才标记改进已生效。
  来源任务已取消不影响独立复盘改进的生效；来源任务被删除或普通任务修复遇到取消时仍停止应用。

验证失败的经验不会用于后续任务。已生效的 Skill 或执行规则可点「后续任务停用」。
已经生效的平台源码修改需要通过平台工程师回退。

## 后续应用和效果

新任务规划时注入匹配的有效经验；第一次执行时补齐适用经验并冻结内容。每个步骤只收到匹配其工具和
能力的经验，记录实际使用的改进项 id 和步骤 id。正在执行的任务不会因后来新增的经验而改变版本。

任务结束后，按实际接收经验的步骤计算每步费用、轮数、失败尝试、成功率和同类问题发生率，与来源
步骤的基线对比。模型、任务能力、难度构成不同的样本不计算效果差值；仅参与规划、尚无实际执行
步骤的记录也不作效果判断。界面展示样本数、原始指标和局限；这些是观察性比较，不证明因果。

重复结束事件不会重复生成；重启会继续未完成的复盘和验证，已经保存的结论不会重生成。
任务的复盘或平台改进仍在处理时不能删除；删除任务会移除关联复盘、改进、观察记录及 Skill 版本文件。
